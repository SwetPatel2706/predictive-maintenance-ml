# Build Spec: predictive-maintenance-ml

This document is a build specification for an AI coding agent (e.g. Claude Code) to scaffold and implement this project end-to-end. Follow it in order. Do not deviate from the folder structure or scope decisions below without flagging it first.

## 1. Project Summary

A predictive maintenance ML project using the AI4I 2020 Predictive Maintenance Dataset. Given machine operating parameters (Product Type, Air Temperature, Process Temperature, Rotational Speed, Torque, Tool Wear), predict whether a machine will experience a failure (`Machine_Failure`: 0 or 1).

This is an academic ML submission (two students, ML course). Scope for this phase is **ML only** — no backend/API, no frontend, no Docker, no databases. Keep the code simple, readable, and well-commented so it's easy to explain to evaluators. A future phase (not part of this build) may add a Streamlit or React+FastAPI app; do not build that now, but don't actively prevent it either.

Source material: an original single-cell Colab notebook (26 steps) is being refactored into a modular Python project. The full original code and all step outputs/figures are available as reference — replicate the same analysis and results, just properly separated into modules.

## 2. Critical Design Decisions (already finalized — do not re-litigate)

- **Target leakage**: `TWF`, `HDF`, `PWF`, `OSF`, `RNF` columns must NOT be used as input features. They are directly related to the target and would leak information. Only these 6 features are used: `Type`, `Air_Temperature`, `Process_Temperature`, `Rotational_Speed`, `Torque`, `Tool_Wear`.
- **Reproducibility**: `RANDOM_STATE = 42` defined once in `config.py`, imported everywhere (train/test split, all three models, GridSearchCV).
- **Class imbalance / recall trade-off**: The dataset is ~96.6% no-failure / ~3.4% failure. The tuned Random Forest achieves Precision ≈0.76, Recall ≈0.65, F1 ≈0.70. This is a KNOWN, ACCEPTED limitation — do not implement SMOTE, threshold tuning, or extra resampling. Instead, `evaluate.py` must print/log a short explicit note explaining that recall is the weaker metric due to class imbalance, and that threshold tuning / SMOTE / cost-sensitive learning are valid future improvements (mention only, do not implement). The README must also state this clearly as a "Limitations" section.
- **Hyperparameter tuning scope**: GridSearchCV is applied ONLY to Random Forest (matches the original project). Logistic Regression and Decision Tree are baseline comparisons only. `evaluate.py` or the README should explicitly state this was a scoping decision, not an oversight.
- **No Colab-specific paths**: All file paths (`/content/...`) from the original notebook must be replaced with relative paths driven by `config.py` (e.g. `data/raw/`, `reports/results/`, `reports/figures/`).
- **Dual execution model**: Every pipeline stage must work BOTH as a standalone script (for the faculty walkthrough — run and inspect one stage at a time) AND be importable/chainable from a single orchestrator script (`run_pipeline.py`) that runs the full pipeline end-to-end in one command.
- **Visuals**: All EDA and evaluation plots must be generated by shared functions in `src/visualization/plots.py`. These functions must (a) save the figure as a PNG to `reports/figures/`, and (b) return the matplotlib figure object so the same functions can be called from the Jupyter notebook to display inline. Do not duplicate plotting code between scripts and notebook.
- **Logging**: All intermediate console output (dataset shape, missing values, duplicate counts, model metrics, etc.) must be both printed to terminal AND written to a log file at `reports/logs/pipeline.log`, via a shared `src/logger.py` module.
- **Notebook imports**: The notebook is NOT part of an installable package. Use a `sys.path` insert at the top of the notebook to make `src/` importable:
  ```python
  import sys
  from pathlib import Path
  sys.path.append(str(Path.cwd().parent))
  ```
  Do not create a `pyproject.toml` / `setup.py` / `pip install -e .` setup — that is explicitly out of scope for this phase.

- **Cross-platform compatibility (macOS + Windows)**: The project must run without modification on both. This affects several things:
  - **All paths use `pathlib.Path`**, never manually joined strings with `/` or `\`. `config.py` defines a single `PROJECT_ROOT = Path(__file__).resolve().parent.parent` and all other paths are built from it with `/` (the `pathlib` operator, which is OS-agnostic — not a hardcoded string separator). Never write `"data/raw/" + filename` string concatenation.
  - **The `sys.path` insert in the notebook** (`Path.cwd().parent`) is already OS-agnostic since `pathlib` handles separator differences internally — no changes needed there, just don't replace it with manual string paths.
  - **`run_pipeline.py` must be runnable from the project root on both OSes**: `python -m src.run_pipeline` (module syntax) works identically on Mac/Windows and is preferred in the README over `python src/run_pipeline.py`, since relative-path execution from arbitrary working directories is a common source of platform-specific breakage.
  - **Virtual environment activation differs by OS** — README must show both:
    - macOS/Linux: `source .venv/bin/activate`
    - Windows (PowerShell): `.venv\Scripts\Activate.ps1`
    - Windows (cmd.exe): `.venv\Scripts\activate.bat`
  - **File writes (CSV, joblib, PNG, logs)** must always go through `config.py` path constants (`Path` objects), and directories must be created with `path.mkdir(parents=True, exist_ok=True)` before writing, rather than assuming the folder exists — this avoids `FileNotFoundError` differences between OSes.
  - **Line endings / encoding**: when writing text files (logs, CSVs), don't hardcode `\n` — let Python's default text-mode newline handling manage it, and default to UTF-8 encoding explicitly (`encoding="utf-8"`) in any `open()` calls to avoid Windows defaulting to a different codepage.
  - **No OS-specific packages**: everything in `requirements.txt` (pandas, numpy, matplotlib, seaborn, scikit-learn, jupyter, joblib) is cross-platform by default — no need for `pywin32` or similar.

## 4. Implementation Order

### Phase 1 — Foundation
1. Create the full folder structure above (with `.gitkeep` placeholders in empty dirs like `data/raw/`, `reports/figures/`, `reports/results/`, `reports/logs/`, `models/`).
2. `requirements.txt`: pandas, numpy, matplotlib, seaborn, scikit-learn, jupyter, joblib.
3. `.gitignore`: standard Python + Jupyter checkpoints + `data/raw/*.csv` (dataset not committed) + `reports/logs/*.log` + `models/*.joblib` (generated artifacts, keep folder via `.gitkeep`).
4. `src/config.py`:
   - `RANDOM_STATE = 42`
   - Path constants using `pathlib.Path` relative to project root (`DATA_RAW_DIR`, `DATA_PROCESSED_DIR`, `MODELS_DIR`, `REPORTS_FIGURES_DIR`, `REPORTS_RESULTS_DIR`, `REPORTS_LOGS_DIR`)
   - `COLUMN_RENAME_MAP` (matches original notebook's renames)
   - `LEAKAGE_COLUMNS = ['TWF', 'HDF', 'PWF', 'OSF', 'RNF']`
   - `FEATURES = ['Type', 'Air_Temperature', 'Process_Temperature', 'Rotational_Speed', 'Torque', 'Tool_Wear']`
   - `TARGET = 'Machine_Failure'`
   - `CATEGORICAL_FEATURES = ['Type']`
   - `NUMERICAL_FEATURES = ['Air_Temperature', 'Process_Temperature', 'Rotational_Speed', 'Torque', 'Tool_Wear']`
5. `src/logger.py`: function `get_logger(name)` returning a logger configured with both a `StreamHandler` (console) and `FileHandler` (`reports/logs/pipeline.log`), consistent formatting with timestamps.

### Phase 2 — Data layer
6. `src/data/preprocessing.py`:
   - `load_data()` — reads CSV from `config.DATA_RAW_DIR`, logs shape, dtypes, missing values, duplicates
   - `clean_data(df)` — renames columns per `COLUMN_RENAME_MAP`, drops leakage columns from any modeling use (keep them in the raw df for EDA reference, but exclude from `X`)
   - `get_features_and_target(df)` — returns `X`, `y` using `config.FEATURES` / `config.TARGET`
   - `split_data(X, y)` — stratified train/test split, `test_size=0.2`, `random_state=config.RANDOM_STATE`, logs resulting shapes
   - `build_preprocessor()` — returns the `ColumnTransformer` (StandardScaler on numerical, OneHotEncoder(handle_unknown='ignore', drop='first') on categorical) — NOT fitted standalone, meant to be embedded in each model's Pipeline
   - All functions must be independently callable (for the standalone script use case) and importable (for `run_pipeline.py`)
   - Add a `if __name__ == "__main__":` block that runs load → clean → split and logs a summary, so it can be run standalone: `python -m src.data.preprocessing`

### Phase 3 — Visualization module
7. `src/visualization/plots.py` — one function per chart, each:
   - Takes data + an optional `save=True` flag and `filename` parameter
   - Saves to `config.REPORTS_FIGURES_DIR / filename` when `save=True`
   - Returns the `matplotlib.figure.Figure` object
   - Functions needed (mirror the original notebook):
     - `plot_failure_distribution(df)`
     - `plot_product_type_distribution(df)`
     - `plot_numerical_distributions(df)`
     - `plot_correlation_heatmap(df)`
     - `plot_feature_vs_failure_boxplots(df)` (one figure per numerical feature, or a combined figure — agent's choice, keep consistent with original notebook's per-feature boxplots)
     - `plot_failure_by_product_type(df)`
     - `plot_confusion_matrix(cm, labels, title)`
     - `plot_roc_curves(models_dict, X_test, y_test)`
     - `plot_model_comparison(results_df)`
     - `plot_feature_importance(feature_importance_df)`

### Phase 4 — Modeling
8. `src/models/train.py`:
   - `build_models(preprocessor)` — returns a dict of the 3 unfitted Pipelines (Logistic Regression with `class_weight='balanced'`, Decision Tree with `class_weight='balanced', max_depth=5`, Random Forest with `n_estimators=200, class_weight='balanced', n_jobs=-1`), all using `config.RANDOM_STATE`
   - `train_models(models_dict, X_train, y_train)` — fits each, logs progress, returns fitted dict
   - `if __name__ == "__main__":` block: runs preprocessing + trains models + logs completion, runnable standalone via `python -m src.models.train`

9. `src/models/evaluate.py`:
   - `evaluate_models(models_dict, X_test, y_test)` — computes Accuracy/Precision/Recall/F1/ROC-AUC per model, returns `results_df`
   - `generate_classification_reports(models_dict, X_test, y_test)` — logs full classification report per model
   - `generate_confusion_matrices(models_dict, X_test, y_test)` — calls `plots.plot_confusion_matrix` per model
   - `generate_roc_comparison(models_dict, X_test, y_test)` — calls `plots.plot_roc_curves`
   - `generate_model_comparison_plot(results_df)` — calls `plots.plot_model_comparison`
   - `log_recall_limitation_note()` — logs the explicit note about class imbalance / recall trade-off being an accepted limitation (see Section 2)
   - `save_results(results_df)` — writes `reports/results/model_comparison_results.csv`
   - `if __name__ == "__main__":` block: runs full standalone evaluation flow via `python -m src.models.evaluate`

10. `src/models/tune.py`:
    - `param_grid` matching the original notebook (`n_estimators`, `max_depth`, `min_samples_split`, `min_samples_leaf`)
    - `tune_random_forest(rf_pipeline, X_train, y_train)` — GridSearchCV, `cv=5`, `scoring='f1'`, `n_jobs=-1`, logs best params + best CV F1
    - `evaluate_tuned_model(best_model, X_test, y_test)` — final classification report, confusion matrix, final metrics
    - `save_best_model(best_model)` — `joblib.dump` to `models/best_model.joblib`
    - `save_final_results(final_results_df)` — writes `reports/results/final_model_results.csv`
    - `save_feature_importance(feature_importance_df)` — writes `reports/results/feature_importance.csv`
    - `if __name__ == "__main__":` block: runnable standalone via `python -m src.models.tune` (assumes train/evaluate already ran, or re-runs minimal setup as needed — agent's judgment, keep it self-contained enough to run independently)

### Phase 5 — Orchestration & notebook
11. `src/run_pipeline.py`:
    - Imports functions from all modules above
    - Runs the full chain: load → clean → split → build preprocessor → train 3 models → evaluate → generate all plots → tune Random Forest → save all results/model/figures
    - Single entry point: `python -m src.run_pipeline` (or `python src/run_pipeline.py` — ensure it works as run from project root)
    - Logs a final summary (matching original notebook's Step 26 summary: best baseline model + final tuned model metrics)

12. `notebooks/exploratory_analysis.ipynb`:
    - `sys.path` insert as described in Section 2
    - Imports `src.data.preprocessing` and `src.visualization.plots`
    - Narrative markdown cells (introduction, dataset description, each EDA step explained) interleaved with code cells calling the shared functions to display plots inline
    - Should read as a presentable, explained walkthrough — this is the primary artifact evaluators will open

### Phase 6 — Docs
13. `README.md` must include:
    - Project title, authors, one-paragraph summary
    - Dataset description (AI4I 2020, source link)
    - Folder structure explanation
    - Setup instructions (venv creation, `pip install -r requirements.txt`) — must include activation commands for macOS/Linux, Windows PowerShell, AND Windows cmd.exe (see Section 2 cross-platform notes)
    - How to run: both standalone module commands AND the single `run_pipeline.py` command, using `python -m src.<module>` syntax throughout (not raw file paths) so commands are identical on Mac and Windows
    - Results summary table (baseline comparison + final tuned Random Forest metrics)
    - **Limitations** section: explicitly state the recall/class-imbalance trade-off and that SMOTE/threshold-tuning/cost-sensitive learning are noted as future work, not implemented
    - **Scope note**: GridSearchCV tuning was deliberately applied only to Random Forest as the strongest baseline, not all three models
    - Future work section (Streamlit or React+FastAPI app — mention only, not built)
